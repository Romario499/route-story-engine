**Контекст**
Спецификация (история 145) предполагала редактор глав в студии: добавить, изменить, удалить, переставить. Первый пользователь сам монтирует ролики и отказался от обязательной ручной работы; 2026-10-12 владелец снял редактор (D03: deferred), порядок приоритетов — достоверность, качество ролика, минимум действий. Сами главы (заголовок, текст, настроение, привязка) остаются; тексты берутся из воспоминаний путешественника (`private/`).

**Решение**
Глава — запись `Chapter` (`anchor`, `mood`, `source`, заголовок и текст; поля `media` нет). Главы подключаются файлом: JSON `Chapter[]` по схеме `public/samples/chapters.schema.json`, выбранный тем же выбором файлов, что и маршрут. Для примера @wahrier в dev файл подхватывается из `private/wahrier/chapters.json`; нет файла — тихо без глав. Глава показывается, только если её `anchor` (страна ISO, где нужно — регион, диапазон меток) совпал с метками загруженного маршрута; несовпавшие пропускаются молча. Файл, не прошедший схему, — понятная ошибка, ролик выходит без глав. Редактора глав в студии нет. В репозитории лежат схема и обезличенный пример; настоящие тексты — только в `private/`. Без глав кадры совпадают с прежними.

**Почему**
- Редактор в студии отвергнут: это и есть обязательная ручная работа, от которой отказался единственный пользователь, а ценность функции, по его словам, не оправдывает времени на неё. Владелец формулирует так: убрать не качество и не возможности, а обязательную ручную работу.
- «Показывать все главы файла» отвергнуто: один файл описывает весь путь, а ролик может быть про участок (деморолик на участке одной страны; ролик «по стране» отложен, G85). Глава о месте, которого в этом ролике нет, подала бы зрителю несуществующий факт.
- Предупреждение о главе без привязки (первая редакция истории 146) заменено молчаливым пропуском: на роликах участка несовпадение — норма, и предупреждение появлялось бы при каждом экспорте.
- Привязка по датам отвергнута: время метки — момент создания закладки, а не визита (ADR 0010). Привязка по стране/региону и диапазону меток; к конкретным ночёвкам глава не привязывается (G80) — файл глав не должен нести точки ночёвок, которые приватность держит вне репозитория.

**Последствия**
- Ручная работа не исчезла, а сведена к одному JSON, который автор пишет по схеме и не правит под каждый ролик. Для человека это всё ещё текстовый файл без подсказок.
- Неприятное: файл, валидный по схеме, но не совпавший с метками (опечатка в коде страны или регионе), даёт не ошибку, а молчаливо пропавшую главу. Единственная защита — внимательно смотреть превью.
- Схема файла глав становится публичным контрактом: как только кто-то напишет свои файлы, поля нельзя менять без совместимости.
- Тексты глав не попадают в сборку и на Pages. Подготовка публичного демонстрационного набора — после согласования с путешественником. Проверка приватности (T15) нашла факты из воспоминаний в отслеживаемых файлах прогона и истории git; решение владельца — очистить до любой публикации.
- Вернуть редактор можно позже без смены формата: он будет писать тот же JSON. Поэтому D03 — deferred, а не «отменено».
